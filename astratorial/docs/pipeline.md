# Cloud pipeline and provisioning

This page describes the optional measured cloud pipeline. The default hackathon flow uses the local illustrated worker: one video with a spoken goal starts a single `generate` job, which transcribes, plans, animates, and narrates without follow-up questions or confirmation. See the [hackathon flow](../README.md#hackathon-flow).

The web application uses Supabase Auth, PostgreSQL/pgmq and two private Storage buckets. Modal runs the durable job consumer and GPU reconstruction. Blender, COLMAP, FFmpeg and PDF parsers never run inside a Next.js request. Astra supplies the reviewed plan, source-image object polygons, Blender instruction code, and visual review; it is not a video-to-3D model endpoint.

## What is implemented

1. The backend inserts a revision-scoped job and queues its ID in `astratorial_jobs`. `/wake` authenticates with `MODAL_WORKER_TOKEN`; a one-minute scheduled drain recovers missed wakeups. `claim_job` grants a 180-second lease. The worker renews it every 40 seconds and immediately before every artifact upload. Loss of the lease cancels processing.
2. Captures are downloaded by a trusted worker, then copied into a fresh Modal sandbox with no network, secrets, shared volumes or cloud credentials. FFmpeg extracts candidate images checked for exposure, exact measurement timestamps, and mono speech. Poppler handles multiple PDF manuals, limited to 10 MB combined and 90 KB extracted text; two overview pages per manual are available, with at most three included in a bounded planning contact sheet. Longer documents ask for relevant excerpts or official links.
3. Astra analyzes the photographs, optional transcribed speech, goal, constraints and manual text. Web search supplies attributable reference pages. Required questions stop generation for context review. An adaptation plan is a template; the new capture and equipment still need independent verification.
4. Only unchanged **room** and **work-area** passes enter one rigid COLMAP reconstruction. Sparse registration, calibrated cameras, CUDA dense stereo and fusion precede Open3D meshing. Faces unsupported by observed points within 2.5 cm are removed. COLMAP 4.2 `mesh_texturer --output_type TXT` produces `mesh.ply` and `texture.png`; the importer retains per-corner UVs and original positions.
5. Physical scale comes from endpoint pairs marked in two separated registered views. Both the scale and independent check should be nonparallel distances (for example width and depth) on the **same horizontal work surface**. The plane establishes world-up, using camera centers to select its upper side. The worker rejects collinear marks, plane residual over 1 cm, unobserved endpoint locations and held-out error above `max(3%, 2 cm)`. The plane becomes Z=0 in Blender, then the manifest and GLB both convert to right-handed Y-up meters. Calibration uses eight actual, well-supported noncoplanar sparse points: six fitting points and two checks.
6. For required movable objects, Astra outlines visible surfaces in up to twelve stationary work-area frames. Calibrated projection with lens distortion and mesh raycasting excludes occluded triangles. At least two agreeing views and 75% visible-view agreement assign a face to an object. Successful parts become separate `SourceItem_*` textured meshes. Supplementary `object`, `open_closed` and `empty_surface` captures are grouped into at most three stationary cohorts, each with six to sixteen frames from one clip. Foreground masks exclude the moving part from camera registration against the fixed base background. Base camera poses and intrinsics remain immutable; new cameras can refine their intrinsics. The base frames are then removed before each cohort's independent dense reconstruction. No contradictory states enter the same stereo model.
7. Object cohorts align through rigid feature matching and ICP against the initial object, with held-out surface checks (at least 65% overlap and no more than 5 mm RMSE). Ambiguous symmetric alignments fail. Newly exposed work surfaces remain in the fixed room coordinate system. Canonical meshes retain their source texture coordinates; named observed transforms describe verified moved or open states for animation. Duplicate co-oriented surfaces are removed across accumulated cohorts while distinct opposite sides of thin objects survive. Combined object coverage requires at least 220 degrees around the object, limited open boundaries, and a dominant connected surface. Missing surfaces or uncertain registration request another capture; no new prop surfaces are invented.
8. Astra writes a real `build_tutorial(ctx)` Blender script. It uses the measured meshes, observed state transforms, supplied human rig and narration timeline. A credentialless, network-blocked Blender sandbox executes it. The wrapper checks source geometry at rest in both directions within 2 mm, bakes rig constraints and object animations, exports one global `tutorial` timeline and step windows, then renders the exported GLB in a new sandbox for visual review against held-out capture views. Initial animation gets at most two repair attempts, counted durably before execution. A source mismatch asks for a recapture.
9. The private delivery contains a detailed GLB plus a mobile GLB of at most 20 MB. Mobile reduction changes texture resolution only (2048, 1024, then 512 maximum dimensions); it does not decimate contact geometry or change the timeline. A scene that still exceeds the bound asks for a shorter/smaller task. The same exported mobile GLB is rendered as the narrated MP4. WAV narration clips use the same step times.
10. Stage bundles, transcripts, segmentation and review state persist in private Storage/SQL checkpoints. The base reconstruction, each supplementary cohort, animation candidates, QA renders and reviews are independently saved. Restarting after a later cohort or QA interruption restores completed work and cannot reset the two-repair limit. Each paid retry receives a fresh reservation ID, retaining unresolved charges from interrupted attempts. A public-copy job also checkpoints its crop and render. Responses requests use `store: false`.

`SceneManifest.rig.handNodes` identifies separate renderable `TutorHand_L` and `TutorHand_R` hand/forearm meshes, sharing the full human armature. Step `handTargets` identifies the object each hand actually contacts. Object positions are support/base contact points. Live correction should translate each hand's already-skinned vertices in world space, as the browser does, and remain within the app's 15 cm same-height bound. Moving a shared skeleton root is not an independent hand adjustment.

## Privacy and publication

Both `captures` and `tutorial-assets` stay private. Storage keys include owner, tutorial and revision. Next.js authorizes every read and hydrates signed URLs. No original capture URL enters a public snapshot.

Publishing creates a separate task-area copy. It physically deletes out-of-bounds mesh vertices for **all** meshes, including the human, using evaluated positions for skinning. It creates fresh UVs and texture atlases, replaces original materials and excludes glTF extras. It renders a fresh poster/video and copies only synthesized narration to `sanitized_narration` assets. Private video recordings and microphone recordings are never copied into public delivery. The backend returns a preview first; the owner's explicit confirmation creates the public snapshot. Cropping can still leave personal objects within the selected task area, so the preview is part of the product flow.

## Voice guard

The browser receives a Realtime WebRTC answer only after Modal has attached the server sideband and acknowledged enforced session settings. The configured model is `gpt-realtime-2.1`; only the trusted guard creates responses. Automatic VAD responses are disabled, maximum output is 512 tokens and post-instruction context is bounded. Unexpected response creation or session tampering ends the call.

Before each response, the guard reserves a conservative input/output ceiling in `voice_sessions` through `update_voice_usage`. Response usage reconciles the reservation without cached-token discounts. The same locked SQL row coordinates `expert_spent_usd` for `ask_astra`; expert calls use their function-call IDs as idempotency keys. Allowed tools are current/repeat/previous/next step, pause/resume, request visual check and ask Astra. The backend resolves tutorial ownership and current state; tool arguments cannot select another tutorial or assert physical completion. Voice instructions cannot automatically mark an action complete.

The guard ends at the shared $2 ceiling or 600 seconds. A separate watchdog ends the call at its stored expiry even if the sideband fails. The scheduled drain also closes expired calls and removes expired camera-check frames. Realtime idle/audio buffering is not itself billed; paid model responses are reserved before creation. User-controlled data-channel events are monitored and unsolicited responses are cancelled, but provider-side access changes should always be regression-tested.

## Provisioning

This checkout has **not** been deployed or run against a real room capture. No Supabase project, Modal environment or replacement API credential was available for a live test. The Blender/COLMAP Docker image has not been built locally: the machine has no working Blender/FFmpeg installation and no running Docker daemon. Passing local Python tests is not a cloud render acceptance test.

1. Create a Supabase project. Apply `supabase/migrations/202609100001_astratorial.sql` with the CLI or project SQL editor. The migration creates pgmq-backed jobs, private buckets, leases, cost reservations, ownership rules and voice accounting. Configure the allowed application URL and Auth redirect URL for the deployed Next.js site.
2. In a Python 3.12 virtual environment install `worker/requirements.txt`, then run `modal setup` for the target managed account. Generate current worker JSON schemas with `node scripts/export-contracts.mjs` whenever `lib/contracts.ts` changes.
3. Copy `worker/.env.example` to ignored `worker/.env`. Supply a replacement OpenAI server key, Supabase service role key, application HTTPS origin and a random worker authentication token. Never reuse the key pasted in a chat or put these values in client environment variables.
4. Review the dated rate ceiling JSON. At the standard Modal Sandbox rates verified on 2026-09-10, four physical CPU cores plus 16 GiB RAM cost $0.0002644/s; adding L4 totals $0.0004864/s. The template uses conservative ceilings of $0.0006/s CPU and $0.0012/s GPU to include trusted orchestration/transfer overhead. These are USD per wall second, not hourly rates, and assume no custom-region or nonpreemptible surcharge. The template retains a deliberately high speech ceiling of $0.001 per character for combined text/audio usage (1,000 characters reserve $1). Speech requests do not expose a final invoice, so this ceiling remains charged to the application ledger. Each narration segment is bounded to 1,500 characters and 1,800 UTF-8 bytes to stay below the speech model's 2,000-token input limit conservatively.
5. Load the secret using `modal secret create astratorial-services --from-dotenv worker/.env`. Deploy with `modal deploy worker/modal_app.py`. The API function returns a Modal HTTPS origin; configure the Next.js `MODAL_WORKER_URL` as its `/wake` path, `MODAL_VOICE_URL` as `/voice`, and the matching `MODAL_WORKER_TOKEN`.
6. Run `modal run worker/modal_app.py::verify_render_image`. This builds the exact image and reports Blender, FFmpeg and COLMAP binary versions plus imported pycolmap and Open3D versions before uploads are enabled. The image pins CUDA 12.9.1/Ubuntu24.04, COLMAP4.2.0, pycolmap4.2.0, Open3D0.19.0, Blender5.2.1 (official archive SHA-256 verification), and the MakeHuman source commit listed below. This CPU smoke check does not validate GPU stereo or rendering. If the build, import checks or subsequent GPU acceptance fail, keep the worker service unconfigured in the web deployment.
7. Run the fixture tests locally and then complete the live acceptance checklist below. Set the hosting platform's server environment variables and deploy the Next.js app after the worker endpoints and Supabase configuration are ready.

```sh
python3.12 -m venv worker/.venv
worker/.venv/bin/pip install -r worker/requirements.txt
node scripts/export-contracts.mjs
worker/.venv/bin/python -m unittest discover -s worker/tests -v
worker/.venv/bin/python -m compileall -q worker/astratorial worker/sandbox worker/modal_app.py
```

Local verification completed 29 orchestration/math/security tests in the normal Python 3.14 worker environment. That run discovers 35 tests and skips six native cases when pycolmap/Open3D are unavailable. All six native cases passed separately with pycolmap 4.2.0, Open3D 0.19.0, NumPy 2.2.6 and Pillow 11.3.0 in Python 3.11. They exercise real rigid ICP with held-out points, rejection of symmetric alignment, radial camera projection and occlusion, thin-surface preservation, overlap/UV deduplication, and registered-frame removal without changing base poses. The orchestration fixtures exercise per-cohort recovery, candidate reuse after QA interruption, the persistent repair limit and budget-pause classification; cloud execution itself is a fixture boundary. The deployed images target Python 3.12 and still require their image smoke check.

To run native cases in an equivalent Python 3.12 environment:

```sh
python3.12 -m venv /tmp/astratorial-native
/tmp/astratorial-native/bin/pip install numpy==2.2.6 Pillow==11.3.0 pycolmap==4.2.0 open3d==0.19.0
/tmp/astratorial-native/bin/python -m unittest discover -s worker/tests -p test_native.py -v
```

Every paid stage reserves within the revision's $25 generation ledger before executing; no operation silently raises the budget. Compute reservations include 120 seconds of setup/transfer allowance. Unknown API outcomes retain their ceiling. A measured provider cost above a configured ceiling is recorded in full and processing pauses; the ledger must never conceal that overflow. Provider pricing, unbounded tool-context changes or infrastructure billing can invalidate an estimate, so this application ledger is not an OpenAI/Modal billing-account hard limit. Verify ceilings before enabling paid work and maintain provider-level limits as operational controls.

The verified standard-context model prices used in the template are Astra input $10/output $50 per million tokens and Realtime audio input $32/output $64, text input $4/output $24 per million. Astra context is constrained below the long-context pricing threshold. Web-search and speech/compute ceilings must be reviewed when provisioning. These values are configuration, not embedded model conclusions.

## Remaining acceptance work and limits

- Test one actual guided scan each for a household appliance, cooking task and assembly task; verify measured dimensions, source textures, every hand contact, overlay drift, and the video/GLB timing. Reflections, glass, low texture, occlusion and moving subjects can require recapture. A successful photogrammetric reconstruction is source-faithful within its measured checks, not proof of an exact unseen room.
- Supplementary reconstruction is implemented for rigid objects or individually segmented rigid moving parts and newly exposed static surfaces. Capture each state while the object remains still and keep distinctive unchanged background in view. Deforming objects, fluids, articulated assemblies without separable rigid parts, symmetric ambiguous states and states lacking source overlap require a narrower task or better captures. Neither cohort selection nor the complete CUDA reconstruction has yet been accepted on real household videos; validate successful and recapture cases before advertising reliable coverage.
- The generic instructor uses MakeHuman Community's CC0 core body, default rig and skin weights from commit `a8bc2d54ff0ac92e78ff71431b1023eda42bf482`. Attribution and source checksums are generated in `/opt/tutor/attribution.json`; public scene notes retain attribution. The detailed human mesh is real, but the skin and utility clothing currently use PBR materials rather than a photographic skin/garment asset. Photorealistic human appearance and natural motion still need live visual acceptance; do not describe that as verified.
- Validate the built Blender 5.2 exporter/importer preserves the single global animation clip, rigged hand meshes, GLB corner UVs and public export skinning. The local machine cannot execute these binaries. Native geometry tests validate the listed CPU algorithms, not the Blender pipeline or COLMAP CUDA CLI.
- Check the mobile GLB is at most 20 MB; compare detail/mobile vertex positions and all hand contacts (texture-only reduction should introduce zero geometric error). Verify narration and video synchronization at every step. Measure on-device performance with real files; no physical-phone performance claim has been made.
- Attempt cancellation/deletion during an upload and a worker crash after an API reservation. Confirm leases prevent stale uploads and charged/unknown attempts cannot be authorized twice. Inspect both public files and network requests to ensure original room atlases, captures and camera frames are absent.
- Exercise voice expiration, budget exhaustion, expert/voice races, illegal tool IDs, data-channel response creation, and a disconnected sideband/watchdog before allowing production calls.
